# Практична робота №36

## Ознайомлення з технологією Minimal API

**Мета:** ознайомитися зі структурою ASP.NET Core Minimal API, налаштувати маршрут і перевірити обмін даними через HTTP.

Створено новий вебпроєкт **PostService** командою:

```powershell
dotnet new web --name PostService --framework net10.0
```

У `Program.cs` стандартну відповідь `Hello World!` замінено на точний текст **«Це API поштового клієнта.»**. Для запуску встановлено адресу `http://localhost:5050`.

## Запуск

Потрібен **.NET SDK 10**. Завантажте репозиторій через **Code → Download ZIP**, розпакуйте й відкрийте термінал у кореневій папці.

```powershell
dotnet build PostService/PostService.csproj
dotnet run --project PostService
```

Поки сервер працює, відкрийте в браузері `http://localhost:5050/` або виконайте HTTP-запит у другому терміналі:

```powershell
Invoke-RestMethod -Uri 'http://localhost:5050/' -Method Get
```

Відповідь:

```text
Це API поштового клієнта.
```

Для перевірки в редакторі додано [test-api.rest](test-api.rest). Його можна виконати через HTTP-клієнт редактора, який підтримує цей формат. За умовою достатньо HTTP-запиту або `.rest`; у цій роботі відповідь фактично перевірено HTTP-запитом.

Зупинення сервера — **Ctrl+C** у терміналі запуску.

## Основний код

[PostService/Program.cs](PostService/Program.cs):

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.WebHost.UseUrls("http://localhost:5050");
var app = builder.Build();

app.MapGet("/", () => "Це API поштового клієнта.");

app.Run();
```

- `CreateBuilder(args)` готує конфігурацію, сервіси та середовище.
- `UseUrls` задає локальну адресу й порт.
- `Build()` створює застосунок.
- `MapGet` зіставляє метод GET і шлях `/` з обробником.
- `Run()` запускає сервер, який очікує запити.

Цей ендпойнт повертає **звичайний текст**, тому його Content-Type — `text/plain; charset=utf-8`. JSON у цьому конкретному маршруті не потрібний.

## Результат перевірки

Збірка завершилась без помилок і попереджень. Реальний запит `GET http://localhost:5050/` повернув **HTTP 200** та точний текст **`Це API поштового клієнта.`**. Також перевірено тип вмісту відповіді.

Фактична відповідь і результати перевірок збережені у [reports/http-response.txt](reports/http-response.txt).

## Короткий висновок

Створення проєкту через `dotnet new web` надало мінімальну структуру вебзастосунку. Для власного ендпойнта достатньо визначити GET-маршрут у `Program.cs` та повернути потрібний текст. Фіксований порт дозволив однозначно визначити адресу, а HTTP-запит підтвердив роботу сервера й правильність відповіді.

## Відповіді на контрольні запитання

1. **Що таке REST API?** Це програмний інтерфейс для роботи з ресурсами за принципами архітектурного стилю REST. У вебсервісах клієнт звертається до URI ресурсів через HTTP, а сервер повертає їхні подання та статус виконання.
2. **Які основні HTTP-методи використовуються?** `GET` — отримання даних, `POST` — створення ресурсу або виконання операції, `PUT` — заміна представлення ресурсу, `DELETE` — видалення. Часткове оновлення часто виконують через `PATCH`.
3. **Що таке ендпойнт?** Доступна точка API, яку визначають HTTP-метод і шлях. У цій роботі це `GET /`.
4. **Чому у веб-API використовують JSON?** Він має текстовий формат, підтримує об’єкти, масиви й прості значення та обробляється бібліотеками багатьох мов. Це спрощує обмін між різномовними програмами. REST не вимагає виключно JSON: наш початковий маршрут повертає текст.
5. **Що таке Minimal API?** Підхід ASP.NET Core до побудови HTTP-API з прямим оголошенням маршрутів і обробників, без обов’язкових класів контролерів.
6. **Які переваги Minimal API?** Мало початкового коду, просте визначення маршруту, швидке створення невеликих сервісів і доступ до можливостей ASP.NET Core — конфігурації, впровадження залежностей та middleware.
7. **Яка роль маршрутизації?** Вона обирає обробник за шляхом і HTTP-методом запиту. `MapGet("/", ...)` визначає обробник кореневого GET-запиту.
8. **Як взаємодіють клієнт і сервер у проєкті?** Клієнт надсилає GET-запит на `http://localhost:5050/`. Сервер виконує обробник і повертає статус 200 та рядок у UTF-8. Клієнтом може бути браузер, PowerShell або програма іншою мовою.
9. **Для чого призначені папки проєкту?** `PostService` містить код і файл `.csproj`; `Properties` — профілі локального запуску в `launchSettings.json`. `bin` містить результати збірки, `obj` — проміжні файли; вони не додаються в репозиторій. Додана папка `reports` містить результати перевірки. `appsettings.json` і `appsettings.Development.json` — файли конфігурації, а не папки.
10. **Що потрібно знати перед створенням ендпойнта?** Призначення ресурсу, URI та маршруту, HTTP-методу, параметрів запиту, обробника, статус-коду, тіла й типу вмісту відповіді. Для перевірки також потрібні фактична адреса та порт сервера.
